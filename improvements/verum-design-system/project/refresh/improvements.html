01 Today queue — the cross-module inbox

A single, ranked list of "things I need to do right now," indifferent to which module produced them.

Pain

Today, to answer "what do I need to deal with?", an engineer opens the Dashboard, then Requirements review queue, then Verification failures, then Issues assigned-to-me, then Documents awaiting my sign-off, then Tasks overdue, then notification bell — five clicks, six modules, then they forget which had the urgent one. Sign-offs frequently slip not because they're hard but because they're invisible.

Fix

One Today screen that pulls every actionable item — sign-off requests, failed runs you own, suspect links you cleared last week, mentions, overdue tasks, CR reviews — and ranks them by deadline + criticality. Inline actions: approve, request changes, re-run, snooze. The bell icon's only job becomes "you have new items in Today."

02 Failure triage drawer — fail → issue → CR → re-run, in one motion

The single most common path in the tool — "a verification failed, now what?" — is currently five screens. Make it one.

Pain

Today: open Verification, see VER-0301 red, click into it, copy the run ID, switch to Issues, click New, paste, link the requirement (which requires opening Requirements in another tab to find the right one), assign someone, go back to Verification, find a place to record "investigating", switch to Change Requests, open new CR, link… seven tabs and twenty minutes. By the time you're done, half the context is lost.

Fix

One triage drawer opens from any failed run. It already knows the run, the requirement, the previous passing baseline, and the suspected delta. It offers three buttons: investigate (creates an issue with everything pre-filled), propose change (creates a CR draft), or retest (queues a re-run). Pick one or several; the drawer assembles the links between them automatically. AI suggests a title and likely root cause from the run logs.

03 Action-first command palette (⌘K)

Stop hunting menus. Type the verb, see the object, hit return.

Pain

The current ⌘K is a search box; it finds things. But day-to-day, engineers want to do things — "release the 17 reviewed reqs", "re-run failed verifications", "open the audit pack", "sign off SDP". Each currently takes 3–8 clicks across a couple of pages.

Fix

A two-mode palette. Plain typing is still global search (today's behavior). Typing a verb first — release, re-run, link, sign, export, baseline — switches into action mode and offers actionable candidates, scoped to context. Hit ⌘↩ to execute. Power-users acquire ten muscle-memory shortcuts and become 4× faster.

04 Smart suspect-link resolver

When a baseline shifts, batch-revalidate dozens of suspect items with AI-summarized deltas. No more whack-a-mole.

Pain

A baseline rolls forward. Twelve requirements, six hazards and a handful of verification plans get flagged suspect. The engineer must click into each one, read the diff, decide if the change still applies, and re-validate. It's death by a thousand cuts and people put it off — which is why the suspect badge sits at 12 for weeks.

Fix

A dedicated resolver that summarizes the delta for each suspect item (old value vs new, with the upstream change linked) and recommends one of three actions: keep as-is (nothing meaningful changed), re-affirm with note (compatible change, add evidence), or open CR (incompatible, action needed). Bulk-select rows, hit "Re-affirm all green," done.

05 Always-on audit pack readiness

Stop building the audit pack at the end. Show its completeness daily, with explicit gaps.

Pain

Today, the audit pack is built as a deliberate end-of-phase action. Gaps — a missing sign-off, an un-released test report, an unlinked hazard — only surface when someone clicks "Build pack" in the last week before submission. Result: a frantic 10-day scramble where people are chasing missing evidence instead of doing engineering.

Fix

The pack is continuously assembled. A single readiness gauge sits in the project header (and on the dashboard) and is updated on every commit. Click in and you see exactly which sections are gating, who owns the next step, and a one-click "build current draft." When the gauge hits 100%, you're already submitting.

06 Auto-link suggester

When you create a hazard, requirement, or task, the system guesses which 3-5 items it should be linked to.

Pain

Most missing-link audit gaps are not because engineers don't want to link items — it's because they don't remember which requirements relate to a new hazard they just wrote. The current workflow is: write hazard, hit save, mentally note "I should link this to something," forget, audit gap appears 8 weeks later.

Fix

On every create form, after typing the title/text, surface a "links you probably want" strip — 3-5 ranked candidates based on text similarity, function/PBS node, and historical linking patterns from this and similar projects. One click links each. Massively reduces the "11 missing links" backlog that gates audit pack readiness.

07 Saved views — role-shaped not feature-shaped

Built-in starter views shaped around how people actually work, not which module the data lives in.

Pain

A safety lead's morning isn't "open hazards page." It's: "check overdue mitigations, review my FTAs in progress, see what's been suspect-flagged since yesterday, glance at this week's submissions." Today that's six filter operations across three pages every single morning.

Fix

Ship a handful of built-in role views — Safety Lead, V&V Lead, Requirements Owner, Certification, QA Approver, Project Manager — each a curated multi-module dashboard the user lands on by default. They're fully editable; users can save their own variations. View switcher sits as a single dropdown in the topbar. Drops "what filters do I want today?" down to zero.

six built-in role views multi-module, single screen save custom · share with team

08 Universal baseline diff

"What changed since baseline X" in one screen, every module included.

Pain

"What's actually different in B-2026-04-12 vs B-2026-03-22?" requires comparing each module separately — requirements diff in one place, parameters diff in another, hazard changes nowhere. The answer matters for sign-offs, regulator submissions, and stakeholder updates. Today it takes half a day to assemble.

Fix

One diff view that picks two baselines and shows changes grouped by impact: new, modified, removed, suspect-resolved. Each row links to the live record. Filterable by module, owner, DAL. Exportable as a single PDF "changelog for regulators." This becomes the canonical artefact for every milestone communication.

B-2026-03-22 → B-2026-04-12 grouped: new · modified · removed cross-module exportable changelog

09 Keyboard-first everywhere

For power users: j/k to navigate, o to open, e to edit, r to reply, ⌘↩ to commit.

Pain

Engineers spend hours per day in tables — requirements, verifications, hazards, tasks. The mouse round-trip from one row to the next, then to the action button, then to the next row, is the largest hidden tax in the product. People who use Linear, Superhuman, or vim know what they're missing.

Fix

Adopt a small, universal shortcut vocabulary: j/k = next/prev row, o = open detail, e = edit in place, r = reply/comment, x = select, ⌘↩ = commit/primary action, ⌘k = palette, ? = cheat sheet. Identical across every module. A discoverable cheat-sheet overlay (? key) onboards new users.

10 keys, every page ? overlay to discover 4× faster for daily ops

10 Notification clustering & quiet hours

Stop pinging on every keystroke. Cluster related events, respect deep work.

Pain

The notification firehose: REQ-1024 changed, then changed again, then a comment, then a relink, then changed once more — five pings for one "event" in human terms. Engineers turn notifications off entirely, miss the one that actually mattered (a sign-off request).

Fix

Group related events on the same object into a single notification ("REQ-1024 changed 3 times today by M. Tan and L. Rivera"). Promote sign-off requests, blocking failures, and direct mentions; demote everything else into the digest. Respect a per-user quiet window (e.g. 09:00–11:00) where only criticals interrupt. Pair with Today (proposal #01) — the inbox is the source of truth, notifications are just nudges.

cluster by object + author criticals only during quiet hours digest the rest

If we ship only three…

Today (#1), the failure triage drawer (#2), and the audit pack readiness gauge (#5) cover the three highest-frequency, highest-frustration paths in the product. Together they touch every module, take the bell-and-search-bar pattern off life support, and make the audit-submission scramble a memory. The other seven are wonderful — but those three are the wedge.

These proposals are not committed designs — they're a thinking pass. Each has a one-screen mock here for shape; the actual flows would need a round of clickable prototypes and engineering scoping before committing.
